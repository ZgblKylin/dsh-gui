# 泄漏校准示例

用于识别[各类型](../SKILL.md#泄漏类型)背后的判断原则，不是照搬的文本模板。示例中的路径与标识符仅为示意，不代表任何具体仓库的布局。本文件刻意引用泄漏措辞作为校准材料，[探针清单](recall-batteries.md)会排除本技能目录；这里的措辞不构成在其他位置沿用的许可。

## 失效的会话引用

### 有归属文档的决策序号

**泄漏：**「斜杠输入按可见目录解析（决策 21）。」

**修正：**「斜杠输入按可见目录解析，这是「明文引用」决策，归属文档见 `docs/adr/0007-slash-input.md`。」

序号在 HEAD 处解析不到任何引用；决策的名字与归属文档路径在 HEAD 处可解析。每个文件至少要出现一次归属文档的路径（载体支持链接时用链接），后续提及可以只用可检索的名字。

### 没有归属文档的决策序号

**泄漏：**「注册表拒绝重名（决策 7：名字扁平，不做命名空间）。」

**修正：**「注册表拒绝重名；名字扁平，不做命名空间。」

没有提交产物拥有「决策 7」，所以引用被删除；但它承载的事实分句（名字扁平）要独立重述，不能跟着引用一起删掉。

### 审计编号

**泄漏：**「渲染是纯函数：同一快照得到同一字符串（审计 R3）。」

**修正：**「渲染是纯函数：同一快照得到同一字符串。」

仓库里没有对应的审计文档，编号只是会话速记，不承载任何命题。

### 未提交草稿的章节号

**泄漏：**「分层遵循设计稿（v2 §3.2）：`src/core/` 是纯内核。」

**修正：**「分层：`src/core/` 是纯内核。」

没人提交过的草稿，它的 §N 无法解析。对照：「转义按 RFC 9110 §10.1.5 处理」保留，因为外部标准按设计在仓库之外解析；拥有自己章节编号的提交文档也可以按章节引用。

### 计划阶段标签

**泄漏：**「`src/client/` 是外壳（T4）；P-I 迁移拥有适配器。」

**修正：**「`src/client/` 是外壳；适配器位于 `src/client/adapters/`。」

阶段标签指向一份从未落地的计划。用该阶段的产物替换标签。

## 栈与 PR 视角

### 长期保留文本里的栈位置

**泄漏：**「未来的远程后端实现这个接口（沙箱后端是本栈里靠后的 PR）。」

**修正：**「远程后端可以在不改动渲染层的前提下实现这个接口。」

长期保留的文本看不到栈。保留扩展点契约；待办工作的归属处是 PR 本身、`TODO` 或 issue。

### README 里的「本 PR」

**泄漏：**「本 PR 为会话列表增加了基于游标的分页。」

**修正：**「会话列表按游标分页。」

README 比每个 PR 活得久；把机制写成当前事实。

## 变更叙述与版本戳

### 带 PR 编号的往事

**泄漏：**「颜色以前来自 `--surface-*` token，但没有地方定义它们，所以一直渲染回退值；别名 token 修好了这个问题（PR #88）。」

**修正：**「颜色来自别名 token；未定义的 token 会渲染回退值。」

两个仍然成立的事实都保留（当前机制与持续存在的失败行为），用现在时重述。缺陷的经过属于 PR 和它的复盘，不属于代码注释。

### 移除叙述

**泄漏：**「`probe` 字段随本次删除一起消失了；徽标现在走通用投影对。」

**修正：**「徽标走通用渲染路径。」

没见过 `probe` 的读者从其缺失中得不到任何信息。「现在」如果与已删除的过去对照，就是版本戳。

### 已修复回归改成现在时反事实

**泄漏：**「这里以前会对多字节标签做双重编码。」

**修正：**「没有字节长度守卫时，多字节标签会双重编码。」

该回归以现在时反事实的形式保留，并点名那个守卫；「以前」把它归入仓库历史。

### 指代当下的版本戳

**泄漏：**「批渲染在本次改动中是同步的；异步路径属于路线图工作。」

**修正：**「批渲染是同步的。」搁置事项写在调用点的 `TODO(widget-batch):` 里。

「本次改动」「v1」「今天」在合并的瞬间就过期。长期保留的理由文档里，变更经过小节中的历史阶段名（「第一次提交交付了 X」）对当前状态安全；指代当下的形式永远不安全。

## 评审编排

### 评审结论当正文

**泄漏：**「评审否决：缓存解析后的规范。我们保留每次调用重新解析。」

**修正**（写在备选方案小节里）：**缓存解析后的规范**。否决：规范依赖调用时的当前目录，按请求做键的缓存会返回过期的根路径。

备选方案小节是获准的归属处；评审者和轮次不属于理由的一部分。

### 草稿序数

**泄漏：**「截至本说明的第 5 版，加载器也会校验 manifest。」

**修正：**「加载器会校验 manifest。」

已实现的说明陈述交付现实；它自己的修订历史在 git 里。

## 面向评审者的自我辩护

### 为一次类型转换辩护

**泄漏：**「这个 cast 是安全的，它只是没有严格声明可选属性。」

**修正：**「SDK 构造这个对象时填充了所有可选属性；声明的类型比运行时保证更宽松。」

陈述维护者不能破坏的不变量。「它只是……」是无人提问时的辩解口吻。如果代码里看得见这个不变量，删掉注释而不是改写它。

### 诉诸评审权威

**泄漏：**「这是正确的，因为评审者确认了包装顺序。」

**修正**：删除；包装顺序写在函数的 `@returns` 里。

正确性论断引用不变量或测试，从不引用人。

## 复述与推导

### 控制流复述

**泄漏：**「先归一化标签，再截断，再换行。」

**修正**：删除。

注释下面的三行代码已经表达了同样的内容。

### 测试走查

**泄漏：**「这个测试创建会话、发送两条消息、等待第二个回复，然后断言日志有四条记录。」

**修正：**「两次往返必须恰好产生四条日志记录，投影对共享前缀去重。」

只保留非显而易见的断言理由；走查只是复述测试体。

## 试探语与规划残留

### 未标注的搁置

**泄漏：**「现在先急切渲染大概没问题。」

**修正**：删除；该搁置事项已经有 `TODO(widget-batch):` 标记。

没有归属者的试探语就是规划残留。如果还没有标记，写一个（`TODO(name): 每动画帧合并一次`），而不是保留试探语。

### 模糊的容量判断

**泄漏：**「64 KiB 缓冲对大多数情况应该够了。」

**修正：**「64 KiB 能容纳已观察到的最大帧（48 KiB）并留有余量；更大的帧会在 `decode` 里显式失败。」

用真实边界和超限时的失败行为替换试探语。

## 撰写语言残留

### 异语言碎片

**泄漏：**「渲染器跑在 client 端；间距见设计稿。---- 私有 ----」

**修正：**「渲染器跑在客户端；间距遵循 Figma 画板 `widget-badges`。」

工作语言碎片和会话分隔线是转录残留。Figma 画板名保留：它是按设计在仓库之外解析的外部来源。

### 成对文件里的语言残留

**泄漏**（两个文件中都是）：`// 更新这里 before returning`

**修正**（两个文件中都是）：`// Update this before returning.`

只修正一次这个代码块，然后把逐字节一致的围栏复制到两个语言文件。在另一侧用不同译法写注释会破坏配对契约，即使两处注释各自通顺。

## 会改变可见行为的候选

**可疑**：一个导出的 JSDoc 句子写着「目前可用」，生成器把这句话复制进模型可见的清单。

**错误**：只在纯文本清理中改源句子，或只手工改生成出来的清单。

**正确**：追查该源句子的全部生成产物及其下游，改归属处，重新生成每个派生物，并更新拥有它的可运行快照。对模型或用户可见的字符串，还要附上该工程要求的行为证据；如果授权范围里没有拥有该行为的场景，保持措辞不变并报告搁置。

## 保留项

### issue 引用在任何载体上都耐久

**保留：**「这个上限作用于完整渲染值，包括包装（issue #1470 拥有后续工作）。」

不加判断的清理会删掉它，理由是 issue 引用应该放在设计文档里。方向错了：issue 在任何载体都能在 HEAD 处解析，而「#N 拥有后续工作」正是 README 里搁置工作的归属处。设计文档与复盘额外获准的，是引用已合并的 PR 作为证据。

### 失效的名字不算点名归属文档

**删除：**「widget seam 上的徽标渲染器（见 widget-rendering RFC）。」

不加判断的清理把它当作「按主题点名归属文档」保留下来。判据是可解析性而不是形式：没有任何提交文件叫「widget-rendering RFC」，所以这个引用无法解析。能找到有归属的文档就改指向它，否则删除。

### 抑制注释

**保留**（修正后）：`// oxlint-disable-next-line no-non-null-assertion -- the one-element literal guarantees index 0.`

理由分句是必需的文本。当陈述的理由是假的（原文说「上面的循环守卫证明帧存在」，但上下文里根本没有循环），修正理由，永远不要删除。

### 测量出的边界

**保留：**「深度上限（实测：512 层嵌套约 0.15 秒同步；4096 层会阻塞事件循环）。」

测量把常量固定在数据上，避免无依据地调参；「实测」标明这是数据而不是猜测。

### 运行期的旧/新不是变更史

**保留：**「旧连接排空后新连接才接受请求。」

这里的「旧」「新」指交接过程中的两个存活运行期对象，不是仓库状态。变更叙述禁令针对仓库历史，不针对生命周期词汇。

### 运行期自然时间不是版本戳

**保留：**「今天是几号？」

这个提问问的是运行时时钟；「今天」没有与仓库状态对照。由于这段文本会到达模型，任何改写仍然需要拥有该行为的证据。

## 过度纠正陷阱

下面每个陷阱都在一次清理里真实发生过，并在评审中被拦下。删除前先枚举段落的命题。

### 把义务变成认可

**原文：**「这些直接注册是迁移到 slot 之前的例外。」

**过度纠正：**「这些直接注册是获准的例外。」

**正确：**「这些直接注册是迁移到 slot 之前的例外。」

「待迁移」是义务，「获准」把现状说成已经获得认可。改写翻转了句子的情态，同时却变短了。

### 把假设提升为既有功能

**原文：**「未来的基于 IPC 的外壳会继承执行器并覆盖 `spawn`。」

**过度纠正：**「基于 IPC 的外壳继承执行器并覆盖 `spawn`。」

**正确：**「假设中的基于 IPC 的外壳（当前不存在这样的外壳）会继承执行器并覆盖 `spawn`。」

只删未来标记，会把设计示意变成该类已经交付的断言。要显式标注假设，而不只是取消未来标记。

### 连周围的转录一起删掉真事实

**原文：**「门禁提示叙述检查顺序；这段提示文本同时也是构建步骤编译的对象。」

**过度纠正**：整句按叙述删除。

**正确：**「这段提示文本是构建步骤编译的对象。」

半句是叙述，另一半是必须保留的实现耦合。命题共享一行时，删的是分句，不是句子。

### 保留数字却丢掉测量来源

**原文：**「4 MiB 上限是实测的：最大的生成模块是 3.1 MiB。」

**过度纠正：**「上限是 4 MiB；最大的生成模块是 3.1 MiB。」

**正确**：保留「实测」。

没有「实测」，3.1 MiB 读起来像定义而不是观察，将来没人会重新测量再抬高上限。
